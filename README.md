# 넘모리

휴대폰이나 PC에서 [넘모리 플레이](https://byh-playground.github.io/bloom-numori/)를 열고 **1대1 대전**을 선택한다. 한 명이 **새 방 만들기**를 누르고, 다른 한 명은 표시된 네 자리 코드를 입력한다. 양쪽이 연결되면 경기가 시작된다. 병력과 자원의 소속은 각자의 화면을 기준으로 표시한다.

## 로컬 실행

프로젝트 폴더에서 `python -m http.server 8000 --bind 127.0.0.1`을 실행하고 [로컬 게임](http://127.0.0.1:8000/)을 연다. `index.html`은 같은 체크아웃의 JS·CSS·에셋을 읽는다. html-share에 올릴 단일 파일이 필요한 경우 `python pack.py`로 `numori-beta.html`을 내보낼 수 있다.

## 배포

GitHub Actions가 `main`의 브라우저 원본을 Pages에 게시한다. BLOOM PLAYGROUND 메타데이터는 `bloom-game.json`에 있다. Nightly 태그는 `main` 푸시마다 발행된다. 검증한 커밋을 Stable로 승격할 때는 Actions의 태그 발행 워크플로에서 커밋 SHA, 제품 버전, 검증 승인을 입력한다.

## 경기 구조

- 선발대는 중앙 다리 가까이에서 출격한다. 두 번째 부대부터는 수식을 완성한 뒤 중앙 다리나 거인 전선 카드를 누른다. 선택한 경로가 전장에 표시되며, 출격 버튼에서 전선과 병력 수를 확인해 출격한다.
- 양 진영은 중앙 다리와 보급로에 방어 타워를 하나씩 갖는다. 공격 부대는 자신이 간 전선의 타워를 뚫고 공용 본진에 도달한다. 타워와 본진은 사거리 안의 적에게 0.2초마다 자동 사격한다. 다섯 번째 발은 착탄 반경 38 안의 모든 적 병력에 기존 공격력만큼 피해를 입히는 곡사탄이다. 한 발의 공격력은 타워 22, 본진 24이며 본진의 체력은 1,400이다.
- 거인 제단에서 우세를 30초 유지하면 중립 거인을 영입한다. 동수면 시간이 멈추고 우세가 바뀌면 새 진영이 30초를 채운다. 제단 가까이에서 현재 점령 중인 진영, 남은 시간, 제단 안의 병력 수를 확인할 수 있다. 방패 거인, 공성 거인, 투석 거인은 모두 범위공격을 한다.
- `match-session.js`가 싱글과 1대1의 경기 시작·고정 틱·소환·일꾼 배정·승패를 관리한다. 싱글에서만 AI가 작동한다.
- `network.js`는 GameKit의 Nostr 방 탐색과 WebRTC 앱 채널을 사용한다. 코드는 네임스페이스 안에서 방을 찾는 용도이며, 게임 입력은 피어 간 데이터 채널을 통해 보낸다.
- `peer-match.js`는 상대와의 연결 및 두 사람의 재경기 의사를 관리한다. 방장은 명령을 검증해 적용 틱과 순서를 확정하고, 참가자는 그 결과를 재생한다. 주기적으로 전장 상태를 대조한다. 기권은 승패로 기록하고, 연결 중단은 경기 종료 사유로 표시한다.
- `battle.js`와 `economy.js`가 전투·채집 규칙을, `world.js`와 `editor.js`가 각자의 카메라와 수식 작업대를 담당한다. 공용 루프·카메라·공간 검색·난수와 전송 모듈의 버전은 [GameKit 출처 기록](vendor/README.md)에 있다.

## 검수

Playwright 환경에서 `python qa/play.py`는 로컬 원본의 싱글플레이를 PC와 모바일 화면 크기로 검수한다. `python qa/multiplayer.py`는 Chrome 두 브라우저로 1대1 대전을, `python qa/altar_duel.py <주소> --out <결과폴더>`는 같은 경기에서 양 진영의 거인 확보를 검수한다. 배포 주소를 인수로 주면 해당 빌드를 확인한다.

방 탐색에는 인터넷 연결이 필요하다. 현재 직접 연결에 STUN을 사용하며, TURN 중계가 필요한 네트워크 조합에서는 연결이 실패할 수 있다. 두 화면이 함께 진행되도록 참가자의 확인이 밀리면 호스트도 기다린다.

`python qa/two_fronts.py <주소> --out <결과폴더>`는 같은 시드와 수식으로 두 번째 부대를 각 경로에 보내서 첫 교전과 거인 영입을 비교한다.

`python qa/defense.py <주소> --out <결과폴더>`로 두 전선의 첫 교전, 타워 파괴, 본진 공격 장면을 재현한다.

## 전장 렌더링과 템포

기본 전장은 GameKit WebGL2 장치의 공유 아틀라스와 인스턴스 쿼드 배치로 그린다. 가까운 캐릭터는 파츠별 관절을 평가하고, 원거리·밀집 부대는 같은 리그로 만든 공용 자세를 사용한다. 미니맵과 일부 이름표는 별도 Canvas 2D 레이어를 사용한다. WebGL2를 사용할 수 없거나 컨텍스트를 잃으면 Canvas 2D로 표시한다.

경기 메뉴에서 **렌더 성능 보기**를 누르면 현재 전장 드로우콜 수, 제출한 쿼드 수, 최근 프레임 간격 p95를 확인할 수 있다. 브라우저 화면 합성은 전장 드로우콜 계수 밖에 있다. `python qa/gpu_bench.py numori-beta.html --out <결과폴더>`로 100~2,000마리 비교를 실행한다. `python qa/gpu-backend.py`는 서로 다른 아틀라스 뱅크의 픽셀과 컨텍스트 복구를 검사한다.

전투 병종은 초당 43~76 월드 단위로 전진한다. 이동 거리로 걷기 모션을 진행하며, 공격 주기와 투사체 속도는 병종별로 설정한다.
