# 넘모리 v0.1.0 브라우저 플레이 검증

2026년 11월 27일, Windows 11 Home 10.0.26200, Intel Core i7-9750H, Playwright Chromium 156.0.8078.4에서 검증했다. 단일 HTML을 file URL로 열고 시작 전에 네트워크를 오프라인으로 전환했다. 통합 플레이 시드는 123, 시뮬레이션은 30Hz다. PC 1440×900, 모바일 세로 390×844와 가로 844×390 모두 DPR 1로 실행했다. 모바일은 Chromium 터치 에뮬레이션이다.

## 수식 입력 및 생산

실제 MathCore, Battle, Economy, NumoriEditor를 고정 보유량으로 연결했다. 선택·연산·보관·교체는 브라우저 버튼을 직접 클릭했다. 명세 22.1의 정상 수식 10개는 각각 40, 36, 30, 48, 80, 125, 512, 729, 16, 9로 평가됐다. 두 하위 블록 합치기, 소수 차로 나누기, 음수 지수, 중첩 로그·제곱근, 각도 숫자 연결을 포함한다.

0으로 나누기, 음수 제곱근, 밑이 1인 로그, 진수가 0인 로그, tan(90°), 0⁰, 음수 밑의 0.5제곱, 기술적 최대 범위 초과의 여덟 사례에서 입력 뒤 생산 버튼이 비활성화되고 등호 재고가 보존됐다. 숫자와 연산자의 중복 예약, 등호 부족, 각도 밖 숫자 이어 붙이기 또한 차단됐다. 8×5의 끝 숫자를 3으로 바꾸면 24가 되고, 편집 중 모인 자원은 실행 취소 후에도 유지됐다. 원식을 분해해 숫자 예약이 해제되는 점도 확인했다.

목표 30, 남은 인구 44에서 8×4−2를 제출했다. 예상 60, 실제 44, 초과 소멸 16을 확인했다. 원본 숫자·연산자와 등호 1개를 차감했고, 보관했던 숫자 5는 유지됐다. 생산 후 실행 취소 버튼은 비활성화됐다. 일꾼 목표 12에서 3×5는 거부됐고, 3×4를 제출하면 인구 6에서 7로 늘었다. 한도 50에서 512를 제출해 다음 단계 100으로만 확장됐다.

## 대규모 교전

시드 123의 양 팀 방패병을 중앙에 밀집 배치하고 실제 전투, 전장 Canvas, 미니맵, 수식 편집기를 함께 구동했다. 각 단계에서 6프레임 예열 후 36프레임 이상 기록했다. 렌더 제출은 JS가 Canvas 호출을 마친 시간까지다. 입력 열은 실제 숫자 8 클릭에서 두 번째 requestAnimationFrame까지 한 번 측정했다. 인원별 기기 FPS 보증이나 실제 GPU 표시 시각을 추정하는 용도로 사용할 수 없다.

| 시작 개체 | 프레임 중앙 / p95 (ms) | 틱 중앙 (ms) | 렌더 제출 중앙 (ms) | 충돌 후보/틱 중앙 | 적 탐색 후보/틱 중앙 | JS 힙 (MiB) | 클릭→2번째 rAF (ms) |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 100 | 16.7 / 33.3 | 0.4 | 0.9 | 3177 | 450 | 5.82 | 65.2 |
| 500 | 16.7 / 33.3 | 1.3 | 1.3 | 22567 | 7331 | 6.57 | 79.3 |
| 1,000 | 16.7 / 33.4 | 2.2 | 1.5 | 49657 | 15706 | 8.45 | 77 |
| 2,000 | 16.7 / 33.4 | 3.9 | 1.5 | 102275 | 28853 | 8.46 | 97.6 |
| 4,000 | 33.3 / 50 | 8.1 | 1.9 | 217765 | 49718 | 9.25 | 120.9 |

밀집 진형 렌더링을 수정하기 전 4,000개 조건은 프레임 중앙값 299.9ms, 제출 중앙값 235.2ms였다. 수정 후 원거리에서는 같은 진영·주변 위치의 개체를 묶어 그린다. 전투와 생산은 여전히 개별 유닛을 기준으로 한다. 모든 측정에서 클릭한 8이 실제 편집기에 입력됐다. 실물 스마트폰의 처리 성능과 입력 지연, WebKit·Firefox 호환, 플랫폼 간 결정론은 미검증이다.

## 비교 기준과 검증 범위

상용 전투 비교 대상으로 Landfall의 Totally Accurate Battle Simulator 공식 Steam 스크린샷 2번·5번(0부터 집계)을 사용했다. 기준작과 넘모리의 전장·교전 화면을 960×540으로 맞췄다. 정지 화면이 뒷받침하는 범위는 첫인상 선호와 장면의 시각적 완성도다. 실제 조작감 비교에는 양쪽 플레이가 추가로 필요하다. [Landfall 공식 소개](https://landfall.se/totally-accurate-battle-simulator) · [공식 스크린샷 출처](https://store.steampowered.com/app/508440/Totally_Accurate_Battle_Simulator/)

MathLive 공개 mathfield에서 키보드 입력 8·곱셈·5가 LaTeX 곱으로 표시되고, 마지막 피연산자를 Backspace와 4로 교체할 수 있음을 직접 확인했다. 넘모리에서는 복합 수식의 각 숫자·연산자를 눌러 교체하고, 재고를 보면서 두 하위 수식을 독립적으로 보관·결합할 수 있었다. 사람을 대상으로 한 입력 속도, 수정 편의, 게임다운 조작감, 전투 중 인지부하 비교는 미측정이다. [MathLive 실제 편집기](https://mathlive.io/mathfield/)

독립 시각 평가자는 1차와 수정 후 재평가에서 각각 양쪽의 전장·교전 정지 화면을 비교했다. 두 평가 모두 첫인상 플레이 선호와 상용 인디게임처럼 보이는 쪽으로 TABS를 선택했다. 궁병의 실루엣과 조준 표현을 보완한 뒤에도 밀집 상황에서 개별 행동을 읽기 어렵다는 지적이 남았다. 시각 건틀렛은 미통과다. 별도 조작 평가에서는 넘모리와 MathLive 모두 4+3의 마지막 피연산자를 두 동작으로 수정했다.

과검증 감사에서는 새로 만든 수식·경제·전투·화면 경로를 남기고, 모바일 에뮬레이션 FPS 중복 측정과 전체 앱을 매 시나리오마다 다시 여는 작업을 제외했다. 5개 규모 측정은 별도로 실행했다. 결과 보고 뒤 재실행할 수 있는 고정 시나리오와 요청된 캡처를 보존했다.
