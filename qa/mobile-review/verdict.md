# 모바일 작업대 검수 · 0.5.1

**공개 배포본에서 기본 수식을 만들고 소환하는 경로를 통과했다.** 단일 HTML 응답의 SHA-256은 `2691201df743f4210f7321d37020d2a53518afc1907265f1009f52818e93cc31`이다. 기존본은 `a89d69b00d3ece9b1e366554f5f90e58bd4d10fc5486780c1bc7ad786523da4d`이다. [공개 게임](https://ellis-thumbzilla-trends-appointed.trycloudflare.com/numori/)

Chromium 터치 에뮬레이션에서 시드 123, 쉬움, DPR 1로 검사했다. 브라우저의 요소 자동 스크롤을 사용하지 않고 버튼의 실제 좌표를 터치했다. 실제 사용자처럼 보통 크기의 손가락으로 탭할 수 있는지 판단하기 위해 각 키의 중앙·네 변·네 모서리 안쪽이 해당 버튼에 닿는지 확인했다. 스크롤이 필요한 때는 작업대 안에서 실제 터치 제스처를 재생했다.

- 모든 화면에서 `8+3` 제출로 16마리, `3×4` 제출로 24마리가 실제 생성됐다. 표의 스크롤 횟수는 측정 스크립트가 사용한 제스처의 횟수다.
- 모바일에서 `8+` 입력을 멈춘 채 **전장 크게 → 작업대 열기**를 눌렀다. 작성된 식과 카메라 중심·배율이 보존됐다. 전장을 크게 본 상태에서 인구 HUD를 터치하면 작성 중인 수식 8을 유지한 채 인구 확장 작업대로 복귀했다.
- 소수 0.5를 터치하고, 실제 채집으로 확보한 고급 연산자를 적용한 뒤 취소해 0.5로 복원했다. 일꾼 생산·광산 재배정, 교전 지역 이동, 화면 회전 후 작업 선택·수식 보존도 확인했다.
- 작은 화면의 기본 전장은 좁다. 360×640에서 입력 중 전장과 일꾼 줄의 합계는 100px이다. 전장 확대 기능을 사용할 수 있다. 보조 숫자·연산 탭의 높이는 세로 34px, 가로 27px이고, 일꾼·카메라 버튼의 높이는 36px이다.
- 테스트는 에뮬레이터와 PC 마우스로 수행했다. 실제 스마트폰의 손가락 오입력률, 성능과 모바일 Safari는 측정하지 않았다.

1차 후보에서는 짧은 세로 화면에서 소환 버튼 13px가 잘렸고, 가로 모드에서 전장 확대 후 복귀하면 카메라 중심이 변했다. 공개본 재검사에서 두 문제의 기대 동작을 모두 확인했다.
